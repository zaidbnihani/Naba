## 1. نظرة عامة ورؤية المنتج

### 1.1 المشكلة
المستخدم العربي اليوم يتابع الأخبار عبر عشرات المصادر المتفرقة (مواقع، تطبيقات، قنوات تواصل اجتماعي)، مما يؤدي إلى:
- تشتت الانتباه وضياع الوقت في التنقل بين مصادر متعددة
- تكرار نفس الخبر من مصادر مختلفة دون تمييز
- غياب تجربة مخصصة تراعي اهتمامات القارئ الفعلية
- ضعف دعم اللغة العربية (RTL) في كثير من تطبيقات الأخبار العالمية المعرّبة

### 1.2 الحل
**نبأ+** تطبيق أندرويد لتجميع الأخبار العربية من مصادر متعددة وموثوقة في واجهة واحدة، مبني بالكامل بدعم RTL أصلي، مع محرك تخصيص ذكي (مدعوم بـ Gemini) يعيد ترتيب المحتوى حسب اهتمامات كل مستخدم، بالإضافة إلى تجربة قراءة واجتماعية متكاملة (حفظ، إعجاب، تعليق، مشاركة، تنبيهات).

### 1.3 القيمة المقترحة
- تجميع أخبار عربية من مصادر موثوقة (الجزيرة، بترا، الدستور، الغد، كورة، رويترز عربي، سكاي نيوز عربية، العربية، عمون، سرايا، خبرني، وغيرها)
- تخصيص فعلي بالذكاء الاصطناعي وليس مجرد فرز حسب التاريخ
- تجربة عربية أصيلة 100%: RTL كامل، خطوط عربية مخصصة (Cairo، Rubik)
- خصوصية بالتصميم: مفاتيح الـ API لا تُضمَّن مباشرة في التطبيق عند الإنتاج (تُمرَّر عبر Supabase Edge Function)

## 2. المستخدمون المستهدفون وشخصيات المستخدم (Personas)

### Persona 1 — "القارئ السريع" (رامي، 27 سنة، موظف)
يفتح التطبيق 3-4 مرات يوميًا لمتابعة العناوين الرئيسية خلال فترات استراحة قصيرة. يهتم بالتنبيهات الفورية للأخبار العاجلة، ولا يقرأ إلا العناوين والملخصات في أغلب الأحيان.

**احتياجاته:** تبويب "آخر الأخبار" سريع التحميل، تنبيهات عاجلة دقيقة وغير مزعجة، واجهة نظيفة بدون تشتيت.

### Persona 2 — "المهتم بمجال محدد" (لينا، 34 سنة، مهندسة برمجيات)
تتابع أخبار التقنية والذكاء الاصطناعي حصرًا، وتتابع مصادر تقنية عربية معيّنة (عالم التقنية). لا تهتم بالسياسة أو الرياضة إطلاقًا.

**احتياجاتها:** تبويب "مجالات" لتصفية الأخبار حسب التخصص، متابعة مصادر بعينها، حفظ المقالات للقراءة لاحقًا.

### Persona 3 — "المستخدم المخصَّص" (زيد، مستخدم دائم)
يستخدم التطبيق يوميًا ويتفاعل بالإعجاب والتعليق بانتظام، ويتوقع أن يتعلّم التطبيق اهتماماته مع مرور الوقت ويعرض له تبويب "لك" مقالات أكثر صلة تدريجيًا.

**احتياجاته:** محرك تخصيص ذكي فعّال (Gemini)، سجل تفاعلات (إعجابات/تعليقات) يُبنى عليه الترتيب.

## 3. نطاق المنتج (Scope)

### داخل النطاق (In Scope)
- تجميع أخبار عربية من مصادر متعددة عبر NewsData.io
- 5 أقسام تنقل رئيسية: الرئيسية، آخر الأخبار، مصادري، مجالات، حسابي
- تخصيص المحتوى بالذكاء الاصطناعي (Gemini)

- حفظ المقالات، الإعجاب، التعليق، المشاركة
- تنبيهات فورية (FCM) قابلة للتخصيص حسب النوع
- وضع ليلي/نهاري وتخصيص حجم الخط
- بحث في الأخبار

### خارج النطاق (حاليًا)
- نسخة iOS
- نشر محتوى من المستخدمين (User-Generated Content) بخلاف التعليقات والإعجابات
- بث فيديو مباشر
- دعم لغات أخرى غير العربية في واجهة المستخدم

## 4. المتطلبات الوظيفية التفصيلية

### 4.1 التنقل الرئيسي (Bottom Navigation)
5 تبويبات ثابتة بترتيب RTL:

| التبويب | الوصف |
|---|---|
| **الرئيسية** (Home) | نظرة عامة: أبرز الأخبار، عاجل، مقترحات |
| **آخر الأخبار** (Latest) | تغذية زمنية مع تبويبات فرعية: لك / عاجل / الأحدث / الأكثر قراءة |
| **مصادري** (Sources) | قائمة مصادر الأخبار المتابَعة وغير المتابَعة |
| **مجالات** (Categories) | 13 مجالًا موضوعيًا لتصفح الأخبار |
| **حسابي** (Profile) | الإعدادات، التفضيلات، تسجيل الدخول، التفاعلات المحفوظة |

### 4.2 شاشة "آخر الأخبار" — التبويبات الفرعية
- **لك (For You):** ترتيب مخصص بواسطة Gemini AI حسب سجل الإعجاب والمتابعات
- **عاجل (Breaking):** الأخبار المصنَّفة كعاجلة فقط
- **الأحدث (Latest):** ترتيب زمني تنازلي بدون تخصيص
- **الأكثر قراءة (Most Read):** ترتيب حسب معدل الشعبية (Popularity)

### 4.3 محرك التخصيص الذكي (AI Personalization Engine)
**النموذج المستخدم:** Google Gemini 2.5 Flash (عبر REST API مباشر)

**آلية العمل:**
1. يأخذ حتى 25 مقالة كمرشحين لتقليل استهلاك التوكنز وتسريع الاستجابة
2. يبني Prompt يتضمن: آخر 10 عناوين أعجب بها المستخدم، المجالات المتابَعة، المصادر المتابَعة
3. يطلب من النموذج إعادة ترتيب المقالات كمصفوفة JSON من المعرّفات (IDs) فقط
4. عند فشل الاتصال أو الاستجابة، يعود تلقائيًا للترتيب الأصلي (Fail-safe — لا انقطاع للمستخدم)
5. يمكن تعطيله بالكامل من الإعدادات (`aiPersonalizationEnabled`)

**قيد تقني ملحوظ:** مفتاح Gemini API مُضمَّن حاليًا في `BuildConfig` (طرف العميل) — راجع القسم 8 لملاحظات الأمان.

### 4.4 المصادقة (Authentication)
- تسجيل دخول عبر **Google Sign-In** (باستخدام `play-services-auth`)
- **Supabase Auth (GoTrue)** كطبقة مصادقة فعلية، وليس Firebase Auth
- **وضع مجهول (Anonymous):** إذا لم يُهيَّأ Supabase بعد، أو لم يسجّل المستخدم دخوله، يُنشأ معرّف مجهول محلي (`anonymousUserId`) للاستمرار باستخدام التطبيق دون تسجيل
- عند التهيئة الكاملة لـ Supabase، تُستخدم جلسة `signInAnonymously()` كخط أساس، ثم تُرفَّع الجلسة عند تسجيل الدخول الفعلي

### 4.5 مصدر بيانات الأخبار
**المصدر الأساسي:** [NewsData.io](https://newsdata.io) API

**آليتان للعمل (موثّقتان في الكود):**
1. **وضع الإنتاج المخطَّط له:** الاتصال عبر Supabase Edge Function بحيث لا يُضمَّن مفتاح NewsData.io داخل التطبيق إطلاقًا
2. **وضع مباشر (`NewsDataDirectInterceptor`) — للتطوير فقط:** اتصال مباشر بـ NewsData.io عندما يكون المفتاح موجودًا في `secrets.properties` و`ApiConfig.isDemoMode = true`؛ يُستخدم حصريًا أثناء التطوير المحلي

**دعم إضافي:** يوجد `MockDataSource` و`MockNewsInterceptor` لتشغيل التطبيق ببيانات وهمية دون أي اتصال شبكة — مفيد للتطوير والعروض التقديمية دون استهلاك حصة الـ API.

### 4.7 المصادر الموثّقة (Sources Catalog)
مصادر عربية موثوقة مربوطة بنطاقات فعلية على NewsData.io:
الجزيرة نت، بترا، الدستور، الغد، كورة، عالم التقنية، رويترز عربي، سكاي نيوز عربية، العربية، عمون نيوز، سرايا نيوز، خبرني، فكت جو.

### 4.8 التفاعلات الاجتماعية
- **حفظ المقالات (Saved):** تخزين محلي عبر Room Database للقراءة لاحقًا دون اتصال
- **الإعجاب (Like):** يُغذّي محرك التخصيص الذكي مباشرة
- **التعليق (Comment):** عدد التعليقات ظاهر على البطاقة
- **المشاركة (Share):** عبر `ShareUtils` (مشاركة نظام أندرويد القياسية)
- **شاشة "التفاعلات" (Interactions):** سجل موحّد لكل ما أعجب به المستخدم وعلّق عليه

### 4.9 التنبيهات الفورية (Push Notifications)
عبر **Firebase Cloud Messaging (FCM)**، بأربعة مواضيع اشتراك منفصلة يتحكم بها المستخدم:
| النوع | المفتاح |
|---|---|
| تنبيهات عاجلة | `breakingAlerts` |
| أبرز الأخبار | `topStoriesAlerts` |
| أخبار رياضية | `sportsAlerts` |
| نتائج المباريات | `matchResultsAlerts` |

يمكن أيضًا تخصيص التنبيهات حسب مصادر بعينها (`alertSourceIds`)، وتفعيل/تعطيل الصوت (`alertSound`).
**ملاحظة تقنية:** آلية الاشتراك (`TopicSubscriptionManager`) تتوقف بصمت دون أي خطأ إذا لم يوجد ملف `google-services.json` — أي أن التنبيهات تُعطَّل تلقائيًا في بيئة التطوير دون تهيئة Firebase.

### 4.10 الإعدادات وتخصيص التجربة
- **وضع العرض:** داكن / فاتح / حسب النظام (`ThemeMode`)
- **حجم خط العناوين:** 4 مستويات (صغير 0.85x، متوسط 1.0x، كبير 1.15x، كبير جدًا 1.3x)
- **التشغيل التلقائي للفيديو:** قابل للتفعيل/التعطيل
- **تفعيل/تعطيل التخصيص بالذكاء الاصطناعي** بشكل مستقل

### 4.11 البحث
شاشة بحث مستقلة (`SearchScreen`) للاستعلام المباشر عبر معامل `q` في NewsData.io.

### 4.12 الترحيب الأولي (Onboarding)
تدفق ترحيب عند أول تشغيل يتضمن اختيار حد أدنى من المجالات المهتم بها (`onboarding_min_categories`)، مع خيار التخطي، وحفظ الحالة (`onboardingCompleted`) بحيث لا يظهر مجددًا.

## 5. البنية التقنية (Technical Architecture)

### 5.1 الحزمة الأساسية والنمط المعماري
`com.nba.plus` — بنية **Clean Architecture** ثلاثية الطبقات:

```
data/       → المصادر الفعلية (Remote, Local, Repository Impl, Supabase)
domain/     → النماذج والعقود المجرّدة (Model, Repository Interface, UseCase)
ui/         → الشاشات، المكوّنات، الثيم، التنقل (Jetpack Compose)
```

### 5.2 المكدس التقني (Tech Stack)
| الطبقة | التقنية |
|---|---|
| اللغة | Kotlin |
| واجهة المستخدم | Jetpack Compose + Material 3 |
| حقن التبعيات | Dagger Hilt 2.52 |
| قاعدة بيانات محلية | Room 2.6.1 |
| التصفح الصفحي | Paging 3.3.5 |
| تخزين التفضيلات | DataStore Preferences |
| الشبكة | Retrofit 2.11 + OkHttp 4.12 + kotlinx.serialization |
| تحميل الصور | Coil 2.7 |
| الخلفية والمصادقة | Supabase (supabase-kt, gotrue-kt, postgrest-kt) 2.6.1 |
| التنبيهات | Firebase Cloud Messaging 24.1 |
| تسجيل الدخول | Google Sign-In (play-services-auth) |
| الذكاء الاصطناعي | Gemini 2.5 Flash (REST مباشر) |
| التنقل | Navigation Compose 2.8.5 |

### 5.3 نماذج البيانات الأساسية
```kotlin
Article(
  id, title, description, content, url, imageUrl,
  sourceId, sourceName, sourceIconUrl, category,
  publishedAt, isBreaking, popularity, likeCount, commentCount
)
```

### 5.4 قاعدة البيانات المحلية (Room)
DAOs موثّقة: `ArticleDao`، `FollowsDao`، `SavedAndLikedDaos` — لتخزين المقالات المحفوظة، الإعجابات، والمصادر/المجالات المتابَعة محليًا مع دعم عمل التطبيق دون اتصال جزئيًا.

### 5.5 دعم RTL
دعم RTL مطبَّق على مستوى `Application Context` بالكامل (وليس فقط XML):
- `Locale("ar")` مضبوطة كافتراضي في `attachBaseContext`
- `LocalLayoutDirection` مضبوطة صراحة على `LayoutDirection.Rtl` عبر `CompositionLocalProvider`
- `android:supportsRtl="true"` في `AndroidManifest.xml`
- خطوط عربية مخصصة مضمَّنة: **Cairo Variable** و **Rubik Variable**

## 6. تقييم الحالة الحالية للتطوير (Development Status Assessment)

> بناءً على فحص مباشر لشيفرة المشروع المرفوعة، بتاريخ 17 أغسطس 2026.

### ✅ مكتمل ويعمل (Implemented & Wired)
- بنية Clean Architecture كاملة (data/domain/ui) مع Hilt للحقن
- شاشات UI الكاملة للأقسام الخمسة الرئيسية + المصادر + المجالات + البحث + التفاعلات + الحفظ + الملف الشخصي + تفاصيل المقال/المصدر + تسجيل الدخول + الترحيب
- التنقل الكامل بين الشاشات (`AppNavGraph`, `Routes`)
- محرك التخصيص بـ Gemini منطقيًا مكتمل مع معالجة أخطاء وFail-safe فعلي
- الاتصال المباشر بـ NewsData.io (وضع التطوير) يعمل فعليًا مع Pagination عبر `nextPage` token
- طبقة Mock كاملة (بيانات + Interceptor) تتيح تشغيل التطبيق دون أي مفتاح API
- قاعدة بيانات Room مع DAOs للحفظ/الإعجاب/المتابعة
- دعم RTL أصلي على مستوى النظام كاملًا، مع خطوط عربية مخصصة
- منطق المصادقة المجهولة (Anonymous fallback) يعمل بدون أي إعداد خارجي
- `TopicSubscriptionManager` لمزامنة تفضيلات التنبيهات مع مواضيع FCM (بتحقق ذكي من وجود Firebase)

### ⚠️ يتطلب إعدادًا يدويًا قبل التشغيل الفعلي (Configuration-Gated)
- **مفتاح Gemini API**: يجب وضعه في ملف `.env` (`GEMINI_API_KEY`) — بدونه يتعطل التخصيص الذكي بصمت ويعود لترتيب افتراضي
- **Firebase**: يتطلب `google-services.json` حقيقيًا — ملف حالي هو مثال placeholder فقط؛ بدونه، التنبيهات الفورية معطّلة بالكامل
- **Supabase**: `secrets.properties` يحتاج بيانات اتصال حقيقية (URL + anon key) — بدونها التطبيق يبقى في "الوضع التجريبي" (مصادقة محلية مجهولة فقط)
- **مفتاح NewsData.io**: للتطوير المحلي فقط عبر `secrets.properties`؛ **الوضع الإنتاجي المخطَّط له (Supabase Edge Function) غير موجود ككود ضمن هذا المشروع** — أي أن حماية المفتاح في الإنتاج لم تُبنَ بعد فعليًا داخل هذا الأرشيف
- **Signing Config**: يستخدم `debugConfig` حاليًا حسب تعليمات الـ README — يجب إزالته واستبداله بمفتاح توقيع إنتاجي حقيقي قبل النشر على Google Play

### ❌ غير موجود / خارج نطاق هذا الأرشيف
- كود Supabase Edge Function الفعلي لحماية مفتاح NewsData.io في الإنتاج (موجود فقط كنية معمارية في التعليقات، وليس كملف منفّذ ضمن هذا الأرشيف)
- اختبارات وحدة شاملة — يوجد ملف اختبار واحد فقط (`DedupDetectorTest.kt`) يغطي منطق كشف التكرار
- أي آلية CI/CD أو Pipeline نشر
- سياسة خصوصية أو شروط استخدام (مطلوبة لنشر Google Play)
- تحليلات استخدام (Analytics) أو تتبّع أعطال (Crashlytics) — غير موجودة في التبعيات

### 🔍 ملاحظة معمارية دقيقة
هناك مصدرا حماية مختلفان موثّقان في الكود لمفتاح NewsData.io:
1. `NewsDataDirectInterceptor` (طرف العميل، للتطوير فقط، يتطلب `ApiConfig.isDemoMode = true`)
2. تعليق في نفس الملف يشير إلى أن "الوضع الإنتاجي" يفترض المرور عبر Supabase Edge Function

**لم يُعثر على أي كود Edge Function ضمن الأرشيف المرفوع** — هذا يعني أن الحماية الإنتاجية للمفتاح **لم تُبنَ بعد فعليًا**، وهذا نقطة حرجة يجب معالجتها قبل أي نشر على متجر Google Play، لأن ترك المفتاح داخل `BuildConfig` في نسخة الإنتاج يعرّضه للاستخراج من ملف APK.

## 8. المخاطر والتوصيات

1. **[حرج]** بناء Supabase Edge Function الفعلي قبل أي نشر إنتاجي، لمنع تسريب مفتاح NewsData.io من داخل ملف APK القابل للفك.
